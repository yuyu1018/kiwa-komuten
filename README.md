# 木和工務店 トップページ

Figmaの「木和工務店｜トップページ」ノード `1:7` をもとに、HTML・CSS・JavaScriptで実装した静的サイトです。

- デザイン: https://www.figma.com/design/enUgjG7YI9jq6B1loMO8Ad/?node-id=1-7
- 基準サイズ: **1280 × 6208px**
- フォント: **Noto Serif JP Regular / Georgia**
- 本文・説明文の基本サイズ: **スマホ（600px以下）は15px、その他は16〜18px**。主なセクション見出しは **24〜36px** です。
- 写真9点・線画4点・SVGアイコン4種はFigma MCPの書き出しをそのまま保存。代替画像・生成画像・全画面画像の貼り付けは使用していません。
- 実行時の外部ライブラリ・外部フォント・Figmaの一時URLへの依存はありません。

## GitHubでの公開

- 公開サイト: https://yuyu1018.github.io/kiwa-komuten/
- ソースコード: https://github.com/yuyu1018/kiwa-komuten

`main` ブランチにpushすると、GitHub ActionsがJavaScriptの構文を確認し、`dist/` をGitHub Pagesに自動公開します。公開処理は `.github/workflows/pages.yml` で管理しています。画像・フォント・CSS・JavaScriptは相対パスのため、GitHub PagesのプロジェクトURLでも表示できます。

通常の更新はファイルを保存し、コミットしてpushします。

```sh
git add dist README.md
git commit -m "Update website"
git push origin main
```

スクリプトや公開設定も変更した場合は、それらのファイルもコミットに含めてください。GitHubの「Actions」から公開の進行状況を確認できます。

## ローカルで確認

このフォルダで実行します。プレビューにはNode.jsのみ必要です。

```sh
npm run dev
```

ブラウザで http://127.0.0.1:4173/ を開いてください。

- `dist/styles.css` を保存すると、スクロール位置を保ったままスタイルが自動反映されます。
- `dist/index.html`、`dist/app.js`、画像を保存すると、ページが自動更新されます。
- ファイルを保存するだけで確認でき、デプロイや非公開サイトへの反映は不要です。
- ターミナルで `Ctrl+C` を押すと停止します。次回も `npm run dev` で起動してください。

別のポートを使う場合は `PORT=8080 npm run dev` で起動できます。自動更新のない通常のサーバーは `npm start` です。ライブリロード用コードはローカル配信時だけ挿入され、`dist/` のファイルには書き込みません。

## CSSの調整方法

`dist/styles.css` は、基本設定・共通パーツ・各セクションの順に整理しています。各セクションの近くに、レイアウトが切り替わる画面幅の指定を置いています。文字・写真・線画のサイズは、可能な範囲でメディアクエリによる固定値の上書きを減らし、`clamp(最小値, 可変値, 最大値)` と縦横比で管理します。

| 調整したいもの | 変更する指定 | 現在の範囲（標準フォント設定時） |
| --- | --- | --- |
| 本文・通常リンク | `:root` の `--font-body`（600px以下で上書き） | スマホ15px、その他16〜18px |
| 本文・説明文・見出し・補足情報の行間 | `:root` の `--line-height-*`（600px以下で上書き） | スマホは本文2倍・説明文1.9倍・見出し1.6倍・補足情報1.8倍 |
| 日付・補助情報 | `:root` の `--font-small` | 14〜16px |
| お知らせ以外のH2の文字サイズ | `:root` の `--font-section` | 24〜36px |
| お知らせのH2 | `.news h2` | 17〜20px |
| 施工事例・こだわりの小見出し | `:root` の `--font-card` | 17〜20px |
| PCの写真列の右余白 | `:root` の `--content-gutter` | 32〜64px |
| モバイルの左右余白 | `:root` の `--mobile-gutter` | 18〜48px |
| 写真・本文のまとまりの最大幅 | `:root` の `--content-max` | 1280px |
| イベント前後の間隔 | `:root` の `--section-gap` | 96〜160px |
| メイン写真の高さ | `.hero-photo` の `height` | 320〜880px |
| 植物の線画 | `.botanical-position` の `--botanical-width` | 176〜256px |
| 枝葉の根元を隠す量 | `.botanical-position` の `--botanical-bleed` | 6%（SVG内で切り抜き） |
| 家族と家の線画 | `.house-family` の `width` | 400〜735px |
| 木の削りくずの線画 | `.wood-shavings` の `width` | 230〜420px |
| 扉の線画 | `.contact` の `--door-width` | 140〜280px |

例えば本文の上限を変える場合は `--font-body` の `clamp()` の3つ目だけを変更します。`--content-inset` は最大幅から中央寄せ用の余白を自動計算するため、通常は編集不要です。

H2は「03. 共通パーツ」の `h2` に集約しています。お知らせ以外の各セクション・詳細ダイアログで、文字サイズ・行間・字間・上余白が共通です。お知らせだけは「06. お知らせ」の `.news h2` で個別指定しています。色は各欄の文字色を継承します。

通常の写真はグリッドの幅と `aspect-ratio` に合わせて表示します。大画面ではグリッド全体を1280pxまでに抑え、スマートフォンでは写真の幅にも上下限を指定しています。狭い親要素では `min(100%, 最小幅)` を使い、最小値が原因ではみ出さないようにしています。

FV（ブランドビジュアル・メイン写真）とお問い合わせは、左端だけをほかの写真列に揃え、右端は画面端まで広げています。「02. ページレイアウト」の `.brand-visual, .hero-photo, .contact` が共通の指定です。スマホ・タブレットでも左余白だけを共有し、狭いお問い合わせ枠では扉の高さに合わせた下余白を確保します。

4点の線画は元のPNGをHTML内のSVGから参照しています。切り抜き・回転はSVG内にまとめてあり、CSSでは横幅と位置だけを調整できます。スマートフォン・タブレットのお問い合わせ欄では、扉の高さに合わせてボタンの下に余白を確保します。

「私たちの家づくり」の枝葉は、根元をSVG内で少し隠し、画面の右端から伸びるように配置しています。PCでは写真の最大幅による内側余白も計算に含め、広い画面でも根元が画面内に浮かないようにしています。

## アニメーション

写真の枠は固定し、画像だけを上から約1.4秒で開きます。少し拡大した画像が約2秒で本来の大きさに戻り、明るさと彩度も自然に整います。文章は220ms遅れて約1秒、4pxだけ移動して表示します。施工事例は80msずつずらし、写真と文章を別々に表示します。いずれも初回だけ再生し、戻って読んだときは繰り返しません。

PCの写真にポインターを重ねると、約1.1秒かけて1.015倍まで拡大します。リンクは下線が静かに伸び、矢印もゆっくり動きます。お問い合わせの背景は固定し、文章と扉をそれぞれ表示します。スマホでは写真の開きを1.1秒、ズームを1.6秒に短縮し、文章の移動量を3pxに抑えています。

| 調整したいもの | 変更する指定 |
| --- | --- |
| 文章の表示時間 | `:root` の `--reveal-duration`（1000ms） |
| 写真の開く時間 | `:root` の `--reveal-photo-duration`（1400ms） |
| 写真のズームが収まる時間 | `:root` の `--reveal-zoom-duration`（2000ms） |
| 写真の開始時の拡大率 | `:root` の `--reveal-photo-scale`（1.045倍） |
| 文章の移動量 | `:root` の `--reveal-distance`（4px） |
| 文章の時間差 | `:root` の `--reveal-copy-delay`（220ms） |
| 施工事例の表示間隔 | `:root` の `--reveal-stagger`（80ms） |
| 動きの緩急 | `:root` の `--reveal-easing` |

表示対象はHTMLの `data-reveal` 属性で指定します。`photo`（写真）・`copy`（文章）・`card`（写真と `.work-copy` の組み合わせ）・`drawing`（線画）を使います。スマホ用の速度は「14. アニメーション」の600px以下の変数で調整します。表示状態は `app.js` の `initScrollReveals()` で監視します。詳細ダイアログには表示待ちの状態を引き継ぎません。

OSの「動きを減らす」設定では表示アニメーションを使わず、途中で設定を変えた場合も全文を表示します。JavaScript無効時・IntersectionObserver非対応時・印刷時も内容が読める構成です。キーボードでリンクにフォーカスした場合は、その内容を即座に表示します。

## 実装・確認結果

- FV・お問い合わせは各写真列と左端を揃え、右端は画面端まで広げます。写真列は最大1280pxで、広い画面では内側の余白を自動で増やします。スマホでも左余白を共有します。お知らせの最大幅は750pxです。
- 900px以下では上部の開閉メニューに切り替えます。施工事例は1100px以下で2列、600px以下で1列です。イベントは完成見学会と相談会を約55:45の比率とし、600px以下では1列になります。
- 320 / 375 / 390 / 600 / 601 / 768 / 900 / 901 / 1024 / 1100 / 1101 / 1280 / 1440 / 1920 / 2560pxの15種類の画面幅で、横はみ出し・画像欠落・JavaScriptエラーがないことを検証しています。
- モバイルメニュー、ページ内移動、全16種類の詳細表示、Escapeキーでの終了、PCナビの固定を確認しています。
- 別途3840px幅まで確認し、本文16〜18px、主要見出し24〜36px、写真グリッド最大1280px、メイン写真の高さ320〜880pxの上下限が守られることを確認しました。900px前後で文字サイズが滑らかに変化し、スマホ・タブレットの扉がボタンに重ならないことも確認しています。
- 写真は `object-fit: cover` で表示し、縦横比を保ちながら枠に合わせてトリミングします。ホバーとページ内スクロールはOSの「視差効果を減らす」設定に対応しています。

`docs/comparison.html` は初回のFigma再現版の比較です。現在の表示は `docs/screenshots/desktop-1280-layout.png`、`desktop-1920-layout.png`、`tablet-768-layout.png`、`mobile-390-layout.png` を参照してください。確認用の画像・記録は配信対象の `dist/` には含めていません。

## 推測・未指定部分

1. **スマートフォン・タブレット**: 元のデザインはPCのみです。900px以下の上部メニュー、施工事例の2列・1列、600px以下の各欄の1列配置を補完しています。
2. **PC幅と右余白**: FV・お問い合わせは左端をほかの写真列に揃え、右端は画面端まで広げます。写真列は最大1280pxで、広い画面では中央に余白を確保します。PCの写真列の右余白は32〜64px、お知らせは最大750pxです。左ナビは `clamp(240px, 23vw, 320px)`、文字・写真・線画・余白は役割に合わせて `clamp()`・Grid・`aspect-ratio` で調整しています。
3. **各リンクの遷移先**: 下層ページやURLの指定がないため、ページ内リンクまたは詳細ダイアログとして実装しました。詳細には提供された文章・写真だけを表示しています。ストーリー・会社情報・ブログ・採用・プライバシーポリシーの未提供部分は「準備中」です。
4. **電話番号・開催日・住所・延床面積**: `000-000-0000`、`○月○日`、`○○県○○市` など、Figmaの仮情報をそのまま残しています。実在する情報は補っていません。
5. **お問い合わせ**: 実際の受付先が未提供のため、ボタンは窓口準備中の案内を表示します。仮番号への発信や、入力内容を送信する処理は設けていません。
6. **文字の描画**: Figmaと同じフォントファミリー・ウェイトを使用していますが、Chromeとの描画差があります。現在は本文16〜18pxと見出し24〜36pxを基本とする可変サイズのため、元のFigmaから折り返しと縦方向の配置が変わります。

## 検証の再実行

Playwrightが利用できる環境で、ローカルサーバーを起動したまま実行します。

```sh
npm run check
npm run qa
npm run compare
```

Playwrightは開発用依存に記載しています。今回はワークスペース内に既にインストールされているPlaywrightを `PLAYWRIGHT_MODULE` で指定し、Google Chromeを `CHROME_PATH` で指定して検証しました。通常のPlaywrightブラウザを使う場合、これらの変数は不要です。

Figmaの書き出し用URLには有効期限があるため、再取得時はMCPから新しいURLを取得してください。サイト表示自体は保存済み素材を利用するので、有効期限の影響を受けません。

ホスティングの設定は `.openai/hosting.json` に保存しています。配信対象は `dist/` のみです。Figmaの原寸スクリーンショットとブラウザの検証画像はローカルの `docs/screenshots/` に保持しています。
