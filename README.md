# 木和工務店 トップページ

Figmaの「木和工務店｜トップページ」ノード `1:7` をもとに、HTML・CSS・JavaScriptで実装した静的サイトです。

- デザイン: https://www.figma.com/design/enUgjG7YI9jq6B1loMO8Ad/?node-id=1-7
- 基準サイズ: **1280 × 6208px**
- フォント: **Noto Serif JP Regular / Georgia**
- 本文・説明文・通常リンクの基本サイズ: **16px**（PC・スマートフォン共通。日付や補助情報は12〜14px）
- 写真9点・線画4点・SVGアイコン4種はFigma MCPの書き出しをそのまま保存。代替画像・生成画像・全画面画像の貼り付けは使用していません。
- 実行時の外部ライブラリ・外部フォント・Figmaの一時URLへの依存はありません。

## ローカルで確認

このフォルダで実行します。プレビューにはNode.jsのみ必要です。

```sh
npm run dev
```

ブラウザで http://127.0.0.1:4173/ を開いてください。別のポートを使う場合は `PORT=8080 npm run dev` で起動できます。

## ファイル構成

```text
dist/
  index.html              セマンティックなトップページ
  styles.css              配色・寸法・PC / スマートフォンのレイアウト
  app.js                  メニューと詳細ダイアログの操作
  assets/                 Figmaの写真・線画・SVG、フォントとそのライセンス
scripts/
  serve.mjs               依存パッケージ不要のローカルサーバー
  qa.mjs                  Playwrightによる表示・動作・素材の検証
  compare.mjs             Figmaとブラウザ画像の差分計算
  download-assets.py      Figmaから取得した素材のダウンロード記録
docs/
  comparison.html         スライダーでFigmaと実装を重ねて比較
  asset-geometry.json     Figmaの素材13点の基準座標・サイズ
  figma-metadata.xml      Figmaの寸法・ノード階層
  implementation-notes.md 未指定部分の扱い・検証内容
  screenshots/            PC / タブレット / スマートフォン / Figma / 差分画像
```

`dist/` がそのまま配信できる完成ファイルです。ビルド処理は不要です。

## 実装・確認結果

- PCではFV・お問い合わせを右端、その他のセクションと右端の写真を右64pxに揃え、1920px・2560px幅でも実座標を検証しています。
- PCでは左側ナビゲーションを固定。初回のFigma再現版は1280×6208pxで照合済みです。現在は本文16pxの指定に合わせて、文章量に応じて各欄の高さが広がるよう調整しています。写真と線画の元素材を維持し、写真はグリッドの幅と縦横比に合わせて表示しています。
- 320 / 375 / 390 / 768 / 900 / 901 / 1024 / 1280 / 1440 / 1920 / 2560pxの11種類の幅で、本文16pxが適用され、横方向のはみ出し・素材の欠損・JavaScriptエラーがないことを確認しました。
- モバイルメニュー、ページ内移動、詳細表示、Escapeキーでの終了、PCナビの固定をPlaywrightで確認しました。
- 写真のトリミングは `object-fit: cover`、線画はFigmaの元画像内の表示位置・回転・比率をCSSで再現しています。
- アニメーションはホバー時の色・矢印とページ内スクロールに限定。OSの「視差効果を減らす」設定にも対応しています。

`docs/comparison.html` は初回のFigma再現版（16px調整前）の比較です。現在の表示は `docs/screenshots/desktop-1280-layout.png`、`desktop-1920-layout.png`、`tablet-768-layout.png`、`mobile-390-layout.png` を参照してください。スクリーンショットと元の参照コードはローカルの確認用で、配信対象の `dist/` には含めていません。

## 推測・未指定部分

1. **スマートフォン・タブレット**: 指定ノードはPCデザインのみでした。900px以下は上部固定メニュー、600px以下は1列レイアウトとして補完しています。写真の順序・線画・配色・文字の階層はPCを引き継いでいます。
2. **PC幅と右余白**: 901px以上ではFV・お問い合わせは画面右端まで広げ、他のセクションとフッターは右64pxで揃えます。本文幅の上限は設けず、画面幅を活用します。左ナビは `clamp(240px, 23vw, 320px)`、セクション間隔は `clamp()`、写真はGridと `aspect-ratio` で調整しています。画面全体の寸法を比例換算する変数は使用していません。本文は16pxです。
3. **各リンクの遷移先**: 下層ページやURLの指定がないため、ページ内リンクまたは詳細ダイアログとして実装しました。詳細には提供された文章・写真だけを表示しています。ストーリー・会社情報・ブログ・採用・プライバシーポリシーの未提供部分は「準備中」です。
4. **電話番号・開催日・住所・延床面積**: `000-000-0000`、`○月○日`、`○○県○○市` など、Figmaの仮情報をそのまま残しています。実在する情報は補っていません。
5. **お問い合わせ**: 実際の受付先が未提供のため、ボタンは窓口準備中の案内を表示します。仮番号への発信や、入力内容を送信する処理は設けていません。
6. **文字の描画**: 同じフォントファミリー・ウェイトを使用していますが、FigmaとChromeのラスタライズには微小な差が残ります。本文はユーザー指定の16pxに調整しているため、元のFigmaから折り返しと縦方向の配置が変わっています。

## 検証の再実行

Playwrightが利用できる環境で、ローカルサーバーを起動したまま実行します。

```sh
npm run check
npm run qa
npm run compare
```

Playwrightは開発用依存に記載しています。今回はワークスペース内に既にインストールされているPlaywrightを `PLAYWRIGHT_MODULE` で指定し、Google Chromeを `CHROME_PATH` で指定して検証しました。通常のPlaywrightブラウザを使う場合、これらの変数は不要です。

Figmaの書き出し用URLには有効期限があるため、再取得時はMCPから新しいURLを取得してください。サイト表示自体は保存済み素材を利用するので、有効期限の影響を受けません。

ホスティングの設定は `.openai/hosting.json` に保存しています。配信対象は `dist/` のみです。Figmaの原寸スクリーンショットとブラウザの検証画像はローカルの `docs/screenshots/` に保持しています。
